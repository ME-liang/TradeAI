## 0. 结论摘要

| 议题 | 设计结论 |
|---|---|
| 入口形态 | 首页 Hero 区**单一输入框**，同时承载「股票」与「板块」两类查询；结果**分组展示**而非让用户先选类型 |
| 类型识别 | 正则形态分流：**6 位数字 → 强判定股票**；`BK`+4 位 → **强判定板块**；4 位纯数字 → 弱判定板块（可回退文本）；其余 → **双路文本模糊** |

| 与 F-01 的关系 | 两者在同一文件（`index.html` / `main.js` / `style.css`）改动，**建议合并一次交付**，避免二次开版 |

## 1. 目标与非目标

### 1.1 目标

1. 把"想查一只票 / 一个板块"的路径从 **3 步（进列表页 → 找到搜索框 → 输入）压缩到 1 步**。
2. 一个输入框同时解决两类对象查询，**用户不需要先知道"这是股票还是板块"**。
3. 输入后**自动判定类型并跳转到正确详情页**，不出现"跳错页 / 落到默认股票"的静默错误。
4. 任何异常（数据源不可用、超时、无结果）都给出**语义正确**的反馈，绝不把"取数失败"渲染成"没有这个东西"。

### 1.2 非目标（明确排除，留待后续）

| 排除项 | 理由 |
|---|---|
| 拼音 / 首字母搜索（如 `gzg` → 贵州茅台） | 后端无拼音索引，需引入映射表，成本 M+，且有维护负担 |
| 搜索历史、热门搜索词 | 属留存类功能，依赖用户量，单独立项（可并入 F-29 埋点后再做） |
| 财报全文检索、自然语言问句 | 属 F-14（AI 追问）范畴，检索后端完全不同 |
| 跨市场（港股/美股/基金/ETF） | 当前数据源仅覆盖 A 股 + 东财板块，超出数据边界 |
| 独立的搜索中间页（`search.html`） | 与"1 步直达"目标冲突；多命中场景改用**下拉分组 + 查看全部**解决 |

## 3. 查询入参识别与匹配规则

### 3.1 归一化（所有匹配前的第一步）

输入先经过 5 步纯文本处理，得到归一化串 `N`：

| 步骤 | 处理 | 例 |
|---|---|---|
| 1 | 去首尾空白 + 去内部空格/`·`/`。`/`-`（代码场景） | ` 600 519 ` → `600519` |
| 2 | 全角 → 半角（数字、字母、括号） | `ＢＫ１３２５` → `BK1325` |
| 3 | 英文一律大写 | `bk1325` → `BK1325` |
| 4 | 剥离市场前后缀 | `600519.SH` / `sh600519` → `600519` |
| 5 | 剥离名称修饰符（**仅用于匹配比对，不改变展示**） | `*ST 力源` → `力源`；`DR中国平安` → `中国平安` |

> 步骤 5 是本设计的关键细节：A 股有 `ST` / `*ST` / `XD` / `DR` / `N`（新股）等前缀，若不做剥离，"力源信息"的精确匹配会失败，用户会以为搜不到。

### 3.2 形态分流（识别决策树）

```
输入 N
 ├─ 匹配 ^BK\d{4}$              → 【强板块】按板块代码精确查询（不再走文本模糊）
 ├─ 匹配 ^\d{6}$                → 【强股票】按 6 位代码精确查询
 ├─ 匹配 ^\d{4}$                → 【弱板块】先试 BK+N 精确命中；
 │                                 命中 → 板块结果置顶
 │                                 未命中 → 降级为文本模糊（按 4 位数字子串搜代码）
 ├─ 匹配 ^\d{1,3}$              → 【不触发】提示"请至少输入 3 位数字，或输入完整名称"
 └─ 含中文/字母                → 【双路文本模糊】并发查询股票与板块，分组展示
```

**为什么 4 位纯数字要单独成一档**：板块代码在系统内是 `BK1325` 形态，但东财页面与用户口口相传时普遍省略 `BK` 前缀（"1325 那个半导体板块"）。若不处理，用户输 `1325` 会被当成"不合法输入"或被 6 位股票规则拒掉。

**为什么 1~3 位数字不触发**：3 位以下的数字子串命中面过大（`1` 会命中数千只代码），既无信息量又会打满冷缓存。此规则同时也抑制了移动端数字键盘的中间输入态。

### 3.3 匹配分级与排序权重

对文本模糊路径的两个结果集，各自算一个**匹配档位** `L`，再按 `(L 升序, 语义权重降序)` 排序：

| 档位 | 判定 | 权重倾向 | 说明 |
|---|---|---|---|
| **L0 精确** | 代码相等 **或** 归一化名称完全相等 | 最高 | 用户已经知道确切名字，必须置顶 |
| **L1 前缀** | 归一化名称以 `N` 开头 | 高 | "力源" → "力源信息" |
| **L2 子串** | 归一化名称包含 `N` | 中 | "半导" → "半导体" |
| **L3 行业字段** | 股票 `ind` 字段包含 `N` | **最低** | 见 §3.5，需特殊处理 |

**档内（同 `L`）次级排序**：

- 股票：按总市值降序（与 `/api/stocks` 默认排序一致，用户心智连续）
- 行业板块 / 概念板块：按涨跌幅绝对值降序？→ **不用**。改用**代码升序**（东财 BK 代码大体按板块规模/字母序），避免"结果随行情跳动"造成同一次输入两次下拉顺序不同。这一点很重要：**建议列表应在同一天内保持稳定**，否则用户按 ↑↓ 选择会选错。

### 3.4 ⚠️ 关键前提修正：`?q=` 直达**当前不生效**（新发现 N-06）

原清单 F-02 的实现思路写着：

> "在首页 Hero 区复用同一套输入组件 + 提交时带 `?q=` 跳 `stock.html`，`stock.html` 已支持 URL 恢复参数（`list_state.js`）。**纯前端拼接，后端零改动**。"

**经代码核对，这个前提不成立：**

- `stock.html:200` 是 `ListState.load('stock')`，而 `list_state.js:41-42` 在 `load()` 首行就判断 —— **非"返回导航"一律返回 `null`**。
- `isReturnNav()`（`list_state.js:27-33`）只认两种情况：`navigation.type === 'back_forward'` 或 URL 带 `?restore=1`。
- 因此从首页点过去的**全新导航** `stock.html?q=半导体`，`RESTORE` 为 `null`，`stock.html:206` 那段 `state.q = RESTORE.q` **根本不会执行** → 搜索框空白、列表回到默认第 1 页。

**影响**：F-02 不是"纯前端拼接"，必须给两个列表页各加一小段"读 `?q=`（及 `?type=`）直达参数"的逻辑。这使成本从 **S** 上抬到 **S+**（仍属小改动，但必须写进改动清单，否则实施时会踩空）。

**设计取值**：新增直达参数采用**不污染现有 `restore` 语义**的写法 ——

- `stock.html?q=<关键词>`：初始化时若有 `q`，写入 `state.q` 与输入框，并**不**保存/清除 `restore`（避免 `cleanUrl()` 把参数抹掉）。
- `sector.html?q=<关键词>&type=industry|concept`：同上，`type` 用于把用户带到正确的板块分类 tab。
- 与 `?restore=1` 同时出现时，**`restore` 优先**（返回导航语义更强）。

### 3.5 行业字段（`ind`）命中的特殊处理

`/api/stocks:478-480` 把 `ind` 也纳入了子串匹配。直接复用到全局搜索会有一个**体验事故**：

> 输入「半导体」→ 股票侧命中 **数百只** `ind="半导体"` 的个股；板块侧命中「半导体」行业板块。若两者平铺在同一列表，**用户想找的那个板块会被淹没**。

**设计决策**：

1. 全局搜索的股票结果集**只接收 `L0~L2`（代码/名称命中）**；`L3`（仅 `ind` 命中）**不进入个股分组**。
2. 但"输入行业名"是**高频真实意图**（用户想看整个行业）。因此把 `L3` 命中**折叠成一条特殊的"行业入口"结果项**：
   `行业：半导体（共 187 只）→ 跳转 sector.html?q=半导体`
3. 该折叠项排在**板块分组之后**，且明确标注"按行业查看个股"。

> 这一条把"行业命中"从噪声变成导航 —— 是"靠什么赚钱/看哪个行业"这类用户意图的自然出口。

## 4. 数据获取与性能预算

### 4.1 请求编排

```
输入 → 300ms 防抖 → 形态分流 → 按分流结果发 1~2 路请求
                              ├─ 股票：/api/stocks?q=N&page=1&pageSize=8&sort=mcap
                              └─ 板块：/api/boards_list?type=industry&q=N&pageSize=4
                                       /api/boards_list?type=concept&q=N&pageSize=4
```

**关键约束（从 2026-09-23 事故直接继承）**：

| 约束 | 取值 | 理由 |
|---|---|---|
| 防抖 | **300ms** | 与 `sector.html:516` 一致；避免每键触发全量匹配 |
| 单飞（in-flight 去重） | 强制：新请求发出前 **abort 上一个未完成请求** | 否则冷缓存时叠加多轮全量拉取 = 限流诱因 |
| 请求序号 | 递增 `seq`，响应回来时 `seq !== 最新` 直接丢弃 | 防乱序覆盖（慢响应盖掉快响应） |
| 客户端超时 | **1500ms** 后进入"仍在加载"降级态（不 abort，只改提示） | 冷启动实测 9~25s，超时后必须给用户出路 |
| 板块 `type` | **必须显式传**，不接受缺省 | `/api/boards_list` 缺 `type` 时语义不完整 |

### 4.2 缓存命中情况（决定实际体感）

| 场景 | 股票侧 | 板块侧 | 预期响应 |
|---|---|---|---|
| 服务已预热 + 当日已访问过板块页（**主路径**） | 命中内存缓存（5553 条） | 命中落盘缓存（496/504） | **< 100ms**，无外网请求 |
| 服务刚启动、板块尚未预热 | 命中落盘缓存 | 需实时拉取（冷） | 板块侧 **9~25s**，必须走 §4.3 降级 |
| 上一交易日缓存 | 命中落盘旧数据（`data_status=stale`） | 同 | 可用，但**必须标注数据时间** |
| 上游全部不可用 | `data_status=unavailable` | 同 | **禁止**渲染"没有这个东西" |

### 4.3 冷启动与不可用的处理（设计硬约束）

1. **股票结果永远优先返回**：两路请求**不做 `Promise.all` 强等待**，谁先回谁先渲染。用户在 100ms 内看到股票结果，板块分组显示为骨架/加载态。
2. **板块分组独立降级**：板块侧超时或 `unavailable` 时，该分组位置显示 ——
   > 「板块结果暂时不可用（数据源故障，**不代表没有这个板块**）」
   
   并提供「去板块页查看 →」。这句话的措辞是刻意与 `sector.html` 2026-09-23 的修复保持一致，避免同类误报回归。
3. **绝不用空数组表示失败**：前端只依据 `data_status` 判分支，不看 `total===0`（沿用既有铁律）。
4. **不做首页启动预热**：不在首页加载时就打板块全量接口（那会重新引入"每次启动 25 次 clist"的诱因）。改为**首次聚焦输入框时**才预热板块窗口，且仅预热一次。

## 5. 结果分组与歧义处理

### 5.1 分组结构与顺序

下拉面板固定三个分组（空分组不占位）：

| # | 分组 | 来源 | 上限 | 组内排序 |
|---|---|---|---|---|
| 1 | **股票** | `/api/stocks` 的 `L0~L2` | 8 条 | 匹配档位 → 市值降序 |
| 2 | **板块** | `/api/boards_list` 行业 + 概念合并 | 6 条（行业优先，各不超 4） | 匹配档位 → 代码升序；**条目上必须带「行业」/「概念」徽标**区分 |
| 3 | **按行业查看个股** | `L3` 折叠项 | 1 条 | — |

每组超出上限时，组尾出现**「查看全部 N 只股票 →」/「查看全部 N 个板块 →」**，跳转到对应列表页（携带 `?q=`）。

### 5.2 歧义矩阵（逐类给出确定性处理）

| # | 歧义场景 | 示例输入 | 判定 | 处理 |
|---|---|---|---|---|
| A1 | 同关键词既是股票名又是板块名 | 「东财」/「平安」 | 两者都可能 | **不做二选一**，分组同时展示；Enter 默认选**排序第一项**，并在面板底部提示"↑↓ 切换 · Enter 打开" |
| A2 | 4 位数字：板块代码 vs 普通数字 | `1325` | 弱板块 | 先试 `BK1325` 精确命中 → 板块置顶；未命中则按数字子串搜股票代码 |
| A3 | 6 位数字恰好也是某板块名称的一部分 | 极少见 | **强股票** | 6 位数字永不解释为板块（板块代码必带 `BK`），避免把代码当文本搜 |
| A4 | 代码存在但无此标的（如 `999999`） | — | 无结果 | 明确提示「未找到代码 999999 对应的股票」+「在全部个股中搜索」出口。**绝不能**静默跳到 `stock_detail.html`（否则会落在默认的 **贵州茅台 600519**，见 §6） |
| A5 | 板块无成分股 / 代码存在但板块已下线 | — | 无结果 | 提示「该板块暂无数据」，并给板块列表出口 |
| A6 | 股票命中极多（如输入「中国」） | — | 多命中 | 只展示 8 条 + 「查看全部 N 只 →」，**不阻塞**在下拉里滚动 |
| A7 | 空输入 / 纯空格 | — | 不查询 | 面板收起；聚焦时不显示历史（非目标），只显示一行浅色提示"输入股票名称、代码，或板块名称、代码" |
| A8 | 极长输入（>50 字） | — | 不查询 | 截断提示「关键词过长」，不发请求（防滥用） |

### 5.3 回车（Enter）的确定性规则

| 当前状态 | Enter 行为 |
|---|---|
| 有高亮项（键盘或鼠标 hover） | 打开高亮项 |
| 有结果但无高亮 | 打开**第一条**（不区分分组） |
| 无结果 / 请求失败 | **不跳转**，焦点保持在输入框，面板给出错误提示与出口 |
| 输入未过最小长度 | 不跳转，提示最小长度要求 |

> 这条"不跳转"约束很重要：现状 `stock_detail.html:338` 的 `|| '600519'` 默认值会让**任何一次误跳转都变成"莫名其妙打开了贵州茅台"**，用户会认为系统坏了。宁可停在原地给提示。

## 6. 跳转目标详情页对应关系

| 结果类型 | 目标页面 | 参数 | 附加动作 |
|---|---|---|---|
| 股票（任意档位） | `stock_detail.html` | `?code=<6位数字>` | 复用 `stock.html:228-234` 的 `prefetchDetail(code)`（`/api/stock` + `/api/kline`）在跳转前预热，实现秒开 |
| 板块（行业 / 概念） | `sector_detail.html` | `?code=BK<4位>` | — |
| 「查看全部 N 只股票」 | `stock.html` | `?q=<关键词>` | **依赖 §3.4 的新增直达逻辑** |
| 「查看全部 N 个板块」 | `sector.html` | `?q=<关键词>&type=industry\|concept` | 同上；`type` 由分组来源决定 |
| 「按行业查看个股」折叠项 | `sector.html` | `?q=<行业名>&type=industry` | — |
| 板块结果不可用时的「去板块页查看」 | `sector.html` | 无参数（默认第 1 页） | — |

**跳转前必须校验（防静默错误）**：

1. 股票 `code` 必须为 **6 位数字**，且**必须来自结果集**（不是用户原始输入）。禁止把原始输入直接拼进 URL。
2. 板块 `code` 必须匹配 `^BK\d{4}$`。
3. 校验失败 → 停在原地提示，**绝不跳转**。
4. `stock_detail.html:338` 的 `|| '600519'` 默认值建议**保留**（用于旧链接兼容），但**必须**在详情页对该默认做来源标注（或改为"未指定代码时的友好空态"）——作为**独立小项**处理，不并入 F-02 以免扩大改动面。

## 7. 搜索框的交互与状态设计

### 7.1 状态机（8 态）

| 状态 | 触发 | 视觉表现 | 可交互性 |
|---|---|---|---|
| **S0 默认（Idle）** | 初始 / 失焦后 | 灰底输入框 + 放大镜图标 + 占位符「搜索股票 / 板块，如 600519、力源信息、半导体」 | 可输入 |
| **S1 聚焦（Focus）** | 点击 / Tab 进入 | 边框高亮（`--blue`）+ 轻阴影；面板展开，显示提示行（非历史） | 可输入 |
| **S2 输入中（Typing）** | 有输入、未到防抖阈值 | 输入框右侧出现**清除按钮（×）**；面板保持上一批结果并降低透明度，**不闪空** | 可输入 |
| **S3 加载（Loading）** | 防抖到期、请求在途 | 面板内 **骨架屏 3 行**（不整屏 loading）；清缓按钮保留 | 仍可继续输入（会 abort 上一请求） |
| **S4 有结果（Results）** | 响应到达且有命中 | 三分组列表；第 1 项默认高亮；底部固定键盘提示条「↑↓ 切换 · Enter 打开 · Esc 关闭」 | 键盘/鼠标均可选 |
| **S5 无结果（No Match）** | `data_status` 正常 **且** 命中为 0 | 面板文案：「未找到匹配「N」的股票或板块」+ 出口按钮「在全部个股中搜索」（跳 `stock.html?q=N`） | 可改输入 |
| **S6 歧义/需澄清（Ambiguous）** | 输入不满足最小长度（§3.2） | 面板文案：「请至少输入 3 位数字，或输入完整名称」（**不发请求**） | 可改输入 |
| **S7 错误/降级（Degraded）** | 股票侧失败 或 板块侧失败 或 超时 | **按侧降级**：一侧可用则正常显示该组 + 另一组位置显示不可用文案；两侧全失败则整体显示「搜索服务暂时不可用，请稍后重试」+「重试」按钮 | 可重试 |

**S5 与 S7 的语义隔离是本设计的核心**（与 2026-09-23 两次事故同源）：

- **S5** = 取数成功 + 确实没有 → "未找到匹配"
- **S7** = 取数失败 → "暂时不可用"，**绝不说"未找到"**
- 前端**只依据接口返回的 `data_status`** 分流，不依据 `total===0`。

### 7.2 键盘与无障碍

| 按键 | 行为 |
|---|---|
| `↑` / `↓` | 在**跨分组**的扁平序列中移动高亮（不跳过分组标题）；到底回卷 |
| `Enter` | 见 §5.3 |
| `Esc` | 面板收起（若有内容则先清空再收起，"两段式"） |
| `Tab` | 离开输入框，面板收起；`Shift+Tab` 反向 |
| 鼠标 hover | 高亮跟随鼠标（与键盘高亮共用同一态） |

**无障碍（必须实现，成本极低）**：

- 输入框 `role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant`
- 面板 `role="listbox"`，分组标题 `role="group"`，条目 `role="option"`
- 结果数量变化通过 `aria-live="polite"` 播报（如"找到 8 只股票、3 个板块"）
- 图标按钮（清除/搜索）必须有 `aria-label`

### 7.3 移动端

- 桌面：Hero 区输入框，下拉面板宽 **= 输入框宽**，最大高 **360px**（超出滚动）。
- 移动端（`<=768px`，沿用 `style.css:407+` 的既有断点）：输入框全宽；聚焦时面板**吸顶全屏浮层**（覆盖 Hero，避免被软键盘挤压错位），顶部带「取消」返回。
- 输入法：监听 **`compositionstart` / `compositionend`**，拼音输入过程中**不触发查询**（否则打"bandaoti"的中途会连发数次无意义请求，且是冷缓存下的限流诱因）。

### 7.4 视觉规格（复用既有变量，不新造一套）

- 底色/边框/圆角沿用 `stock.html:35-46` 的 `.search` 规格（`--search-bg:#F5F7FA`，focus 时 `--blue` 边框）。
- 首页 Hero 为浅色渐变底，**搜索框需加一层白底 + 中等阴影**才能与 `.hero-arc` 装饰弧线分离；移动端下拉层级 `z-index` 要高于弧线（`style.css:260-286`）。
- 类型徽标：股票用中性灰，**行业**用蓝、**概念**用紫（三个色值可从既有调色板取，不新增语义色）。
- 涨跌配色：**沿用 A 股约定（涨红跌绿）**，搜索结果条目的涨跌幅与全局一致。

## 12. 一句话总结

F-02 的技术难点**不在搜索框本身**，而在两处：**① 把"取数失败"与"确实没有"严格隔离**（避免第三次复现同类误报），**② 修正 `?q=` 直达不生效的既有假设**。前者已由 2026-09-23 的 `data_status` 体系提供现成基建，后者需要两个列表页各加几行——**这也是把它和 F-01 合并成一次交付、而不是"纯前端拼接"的真正原因**。
