## 零、一句话结论

F-01 表面是"把三行被注释掉的 `window.location.href` 恢复"，**实际卡点不在 JS，而在"第三张卡的落点根本不存在"**——`report.html` 从未存在过，`main.js:54` 注释里的路径是个幻觉。因此本方案的核心不是"接通三处跳转"，而是**先回答"每张卡到底该去哪里"，再统一解决卡片的语义与可访问性问题**。

同时有两处与原判断不同的事实，会直接改变做法（见 §1.3）：

1. **第 4 张卡不是虚假宣传**——"年报/中报/单季度视图自由切换 + 同比/环比"**真实存在**，只是实现在**基本面报告模板内部**（`report/template.html:293-294, 303, 722-728`），而不是任何独立页面。
2. **第 3 张卡才是唯一真正撒谎的**——"一键导出可下载的 HTML 分析报告"里，**导出能力完全未实现**（F-07）。

## 二、问题定义

| 编号 | 问题 | 性质 | 严重度 |
|---|---|---|---|
| **P1** | 4 个首屏 CTA 全部无效（3 个只剩 `console.log`，1 个连分支都没有） | 功能缺失 | **P0** |
| **P2** | 卡片 3 的落点 `report.html` **不存在**，且没有任何页面能承接"报告"语义 | 落点缺失 | **P0** |
| **P3** | 卡片 3 的"一键导出"是**未实现承诺**（营销承诺 ≠ 功能） | 信任 / 合规 | **P0** |
| **P4** | 卡片是 `<article>` + JS 跳转，**键盘不可达、无法中键/⌘+点击新开、链接不可复制** | 可访问性 / 可用性 | P1 |
| **P5** | 卡片 4 的文案**指向正确但落点不可直达**（能力藏在报告内部），用户认知链路断裂 | 信息架构 | P1 |
| **P6** | 导航栏 `<a href="#report">智能报告</a>` 指向**卡片自身**（`<article id="report">`），点击只是滚动 | 一致性 | P2 |

> P1+P2+P3 共同构成"首屏转化率的最短路径修复"——清单里 F-01 被列为 **P0 / 成本 S**，评价依据就在这里，但从 §1.3 看，"成本 S"只在**明确了落点策略之后**才成立。

## 三、目标与非目标

**目标**
1. 四张卡**全部可达**且**语义诚实**（文案承诺 = 真实用户能完成的事）。
2. 卡片改为**语义化链接**：键盘可达、可新开标签、可复制 URL。
3. 消除"点了没反应"与"跳错页面"两类事故——**与本项目两次误报事故同一条铁律：绝不把语义不明的状态留给用户猜**。
4. 与 **F-02** 合并一次交付（同改 `index.html`），并**顺带补上 F-02 的随仓回归用例**（N-10）。

**非目标（明确不做）**
- ❌ 不新建「报告库」页（F-06）；不实现导出（F-07）；不实现分享（F-08）。
- ❌ 不改 `stock_detail.html` 的报告生成逻辑（已可用）。
- ❌ 不动移动端 `user-scalable=no`（属 F-31）。
- ❌ 不引入前端框架、不重构 `main.js`（仅删除失效代码）。

## 四、核心设计：四张卡的落点映射

### 4.1 卡片 1、2 —— 无争议，直接确定

| # | 落点 | 理由 |
|---|---|---|
| 1 | `stock.html` | 文案是"输入股票代码"，列表页正是全市场入口 + 已带搜索框；且已支持 `?q=` 直达 |
| 2 | `sector.html` | 板块列表页，与文案"以申万一级行业为基准"直接对应 |

### 4.2 卡片 3、4 —— 三个候选策略（**决策点 D2**）

两张卡的能力都落在 `stock_detail.html`，但首页给不出 code。三个可行策略：

#### 策略 A：统一跳 `stock.html`（零新增语义）
- 做法：卡片 3、4 的 `href` 都是 `stock.html`。
- 优点：改动最小，零新参数、零新 UI。
- 缺点：**与卡片 1 落点完全重复**——用户点"智能投研报告"却到了"个股列表"，会认为是 bug。这正是本项目最忌讳的"语义不明"。

#### 策略 B：带意图参数 + 列表页引导条（**推荐**）
- 做法：卡片 3 → `stock.html?intent=report`；卡片 4 → `stock.html?intent=financials`；`stock.html` 读取 `intent` 后在搜索框下方（`#meta` 位置，`stock.html:155`）显示一条**可关闭的引导条**，明确告知为什么来到这里、下一步做什么。
- 引导条文案（拟）：
  - `intent=report` → 「请先选择一只股票，进入详情页后点「AI生成公司基本面分析报告」即可生成投研报告。」
  - `intent=financials` → 「请先选择一只股票，生成基本面报告后可在报告内按 **年报 / 中报 / 单季度** 切换视图，并查看同比 / 环比。」
- 优点：
  1. **复用 F-02 已建立的直达参数机制**（`stock.html:213-224`，N-06 已修并验证），语义与 `?q=` 同构，不引入新范式；
  2. 引导条**解释了跳转意图**，从根本上避免"点了没反应/跳错页"的二次误报；
  3. `intent` 可作为 F-29 埋点的天然维度；
  4. 不新增页面，成本仍 **S~M**。
- 缺点：需给列表页加约 15 行参数读取 + 一个提示条 DOM/CSS；需处理"用户又手动改了 URL"等边界。

#### 策略 C：卡片 3、4 降级为"不可点击的能力说明"
- 做法：去掉第 4 张卡的手型光标与事件绑定，视觉上弱化 hover，只保留卡片 1、2 为真入口。
- 优点：**最诚实**（4 个 CTA 全死 → 明确变成 2 个入口 + 2 条说明），零新颖道。
- 缺点：与 F-01 标题"卡片与导航打通"的初衷相反；首屏可点面积从 4 降到 2。

> **推荐：策略 B**。理由：F-01 的价值在于"把首屏变成有效入口"，策略 C 放弃了这一价值；策略 A 则用一个**新的语义不明**替换了旧的死按钮。策略 B 是唯一同时满足"可点 + 诚实"的做法，且它复用的是**本仓库刚刚验证过的机制**（直达参数），不引入新概念。

### 4.3 卡片 4 的 `id` 缺失

必须补 `id`（建议 `financials`）。**注意**：命名不要用 `report`（与卡片 3 冲突）。同时 §4.4 的导航锚点兼容性依赖 `id` 的存在。

### 4.4 导航栏一致性

`index.html:35` 的 `<a href="#report">智能报告</a>` 目前指向卡片 3 自身（滚动即可见，无功能）。两种改法：

- **改法一（推荐，与卡片 3 统一）**：`href` 改为与卡片 3 相同的落点，导航与卡片行为一致。
- **改法二（保守）**：保持 `#report` 锚点滚动行为，但把 `id="report"` 明确留在卡片根元素上（这样锚点仍生效）。

> ⚠️ **无论选哪种，`id="report"` 都必须留在卡片根元素上**：因为 §5 要把 `<article>` 换成 `<a>`，若顺手把 `id` 挪到内层 `<h3>`，`#report` 锚点的滚动落点会偏移，且 `main.js` 里以 `id` 判断分支的逻辑（虽然要删）与任何外部引用都会失效。

## 五、交互与可访问性设计

### 5.1 卡片语义：`<article>` → `<a>`（**决策点 D4**，强烈建议采纳）

现状：`<article class="feature-card">` + `card.style.cursor='pointer'` + JS `window.location.href`。

改为：

```
<a class="feature-card" id="stock" href="stock.html"> … </a>
```

| 收益 | 说明 |
|---|---|
| 键盘可达 | 原生可 Tab 聚焦、Enter 触发（现状**完全不可达**） |
| 支持新开标签 | 中键 / ⌘+点击 / 右键"在新标签打开" |
| URL 可复制、可分享 | 现状 JS 跳转无法被复制 |
| SEO / 语义 | 链接是导航语义的正确载体 |
| **零 CSS 成本** | `css/style.css:37-40` 已有全局 `a { color: inherit; text-decoration: none; }`；`.feature-card` 未设 `display`，作为 grid 子项会被自动 blockify → **样式无需改动** |

**必须同步做的三件事**（否则会出现双重导航）：
1. **删除** `main.js:41-57` 整段卡片点击处理（含 `console.log` 与注释掉的跳转）——`<a>` 与 JS 跳转**不能并存**，否则 Ctrl+点击会在新标签打开的同时把当前页也跳走。
2. **删除** `main.js:43` 的 `card.style.cursor = 'pointer'`（`<a>` 天然是 pointer，内联样式反而会覆盖未来的样式调整）。
3. 新增 `:focus-visible` 焦点态样式（现状卡片**无任何焦点视觉**），建议与 `.feature-card:hover` 的 `border-color` 对齐，另加一层可见 outline 以满足 WCAG 2.4.7。

### 5.2 移动端

- 卡片在移动端是单列（`css/style.css:421, 485` 两处 `.feature-grid` 媒体查询）。改成 `<a>` 不影响布局。
- 触控目标尺寸：卡片本身远大于 44×44px，无障碍无虞。
- **不改** `index.html:5` 的 `maximum-scale=1.0, user-scalable=no`（禁止缩放，WCAG 1.4.4 问题）——属 F-31 范畴，本方案仅在 §13.4 记录。

### 5.3 与 F-02 搜索框的共存

Hero 区的全局搜索框（`index.html:63-80`，由 `js/global_search.js` 接管）与功能卡片**物理分离**（一个在 `.hero-copy`，一个在 `.features` 区），不存在点击区域重叠。两个 IIFE（`main.js` / `global_search.js`）各自独立，无共享状态 → **改动互不影响**。唯一耦合点是同一个 `index.html` 文件，故应合并交付。

## 八、验证与验收标准

### 8.1 可测断言（10 条）

| 编号 | 断言 | 验证方式 |
|---|---|---|
| A1 | 四张卡在 DOM 中均为 `<a>` 且 `href` 非空、非 `#` | DOM 断言 |
| A2 | 四张卡均可被 `Tab` 聚焦并显示焦点样式 | 键盘走查 / CDP |
| A3 | Ctrl/⌘+点击卡片**只在新标签打开、当前页不跳转**（验证 JS 跳转已删净） | CDP 手动走查 |
| A4 | 卡片 1 点击 → `stock.html`；卡片 2 → `sector.html` | e2e |
| A5 | 卡片 3/4 的 `href` 与所选策略一致（策略 B：含 `intent=`） | DOM 断言 |
| A6 | **卡片 3/4 的 `href` 绝不含 `stock_detail.html`**（防止静默打开茅台） | DOM 断言（**回归护栏**） |
| A7 | 策略 B 下：`stock.html?intent=report` 显示引导条且文案正确；无 `intent` 时**不显示** | e2e |
| A8 | 策略 B 下：`?intent=` 与 `?q=` 可共存，且 `restore`（返回导航）优先级仍最高 | e2e（复用 N-06 用例） |
| A9 | 导航"智能报告"的行为与卡片 3 一致（改法一）或锚点仍可滚到卡片（改法二） | 点击走查 |

### 8.2 必须跑的既有回归

## 九、边界与风险

### 9.1 必须守住的既有陷阱
- **`stock_detail.html` 无 `code` 会静默打开 `600519`（贵州茅台）**。F-01 的映射表里**禁止出现裸 `stock_detail.html`**，并由断言 **A6** 长期守住。
- **`<a>` 与 JS 跳转不能并存**，否则 Ctrl+点击双重导航（断言 A3 守住）。
- **`id="report"` 必须留在卡片根元素**，否则导航锚点失效（§4.4）。

### 9.2 风险矩阵

| 风险 | 影响 | 对策 |
|---|---|---|
| 策略 B 的引导条被误当成"错误提示" | 用户困惑 | 文案用中性引导语（"请先选择一只股票…"），**不使用警示色**；可关闭 |
| `intent` 参数被外部链接滥用 / 拼错 | 显示无关提示 | 白名单校验（仅 `report` / `financials` 生效），其余忽略且不报错 |
| 卡片改 `<a>` 后用户用 ⌘+点击，落在新标签的列表页而引导条丢失 | 轻微 | 策略 B 的 `intent` 在 URL 里，新标签同样会读到 → **天然兼容** |
| 移动端 4 张卡 + 引导条首屏过长 | 轻微 | 引导条出现在列表页（非首页），首页不受影响 |
| 文案修订被后续迭代改回 | 中 | 在清单文档中登记"卡片文案与已实现能力必须一致"的约定 |

### 9.3 取舍说明
- **不接受**"给卡片 3/4 硬编码一个示例 code"（例如 `stock_detail.html?code=600519`）：虽然马上就能"点得动"，但它会把首页变成"每次点都打开茅台"的假功能——**比死按钮更糟**，因为它看起来是正常工作的。
- **不接受**"先建一个空的 `report.html` 占位页"：会新增一个"有页面没功能"的中间态，与 F-26 短信表"建了不用"是同一类问题。
