# 云端部署 + 手机 APP + 账号密码登录（首次绑定手机号）：可行性与成本方案

> 需求：① 部署到云端；② 产品改为手机 APP 形态；③ 账号密码登录；④ 首次登录强制绑定手机号（短信验证码验证）。
> 项目现状：FastAPI（8002，端点内联、纯 JSON）+ 手写 HTTP 服务（8000，vanilla HTML）+ 零数据库、零用户体系、零 CORS；服务绑 127.0.0.1/0.0.0.0，无公网。

## 一、可行性结论（先说判断）

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 技术可行性 | ✅ 高 | 现有 FastAPI 全 JSON 接口可直接作 APP 后端；账号密码 + 短信绑定是标准方案；SQLite 三表（users/sessions/sms_codes）零新增依赖（`hashlib.scrypt` 存密码、`requests` 发短信） |
| 云端部署可行性 | ✅ 高 | 大陆服务器需 ICP 备案（免费、7~20 工作日）；已有成熟路径 |
| **应用商店上架** | ⚠️ **最大风险** | 你的产品含 A 股行情/个股分析，属"金融理财"敏感类目。华为/小米/苹果等商店对股票类 APP **强制要求《经营证券期货业务许可证》+ 交易所行情授权书 + 软著 + APP 备案**（苹果还要求《境内金融信息服务备案》）。个人/小团队拿不到证券牌照 → **大陆应用商店上架基本不可行** |
| 绕行路径 | ✅ 可行 | ① **不上架商店**：安卓直接分发 APK 安装包、iOS 走 TestFlight（内测）/PWA 添加到主屏；② PWA 网页应用形态；③ 海外 Google Play（行情类宽松，但大陆访问受限）；④ 与持牌机构合作（长期） |


**推荐：走"云端 + 不上架"路线**——APP 用 PWA 或 WebView 套壳（Capacitor），安卓用户直接装 APK，iOS 用户用 PWA/TestFlight，功能不受影响，绕开牌照门槛。后续若拿到资质再走商店上架。

## 二、APP 形态选型

| 形态 | 开发量 | 现金成本 | 体验 | 适用 |
| --- | --- | --- | --- | --- |
| **PWA**（manifest + service worker，浏览器添加到主屏） | ≈0.5 人日 | **0 元** | 接近原生，无推送、无应用商店 | 推荐首版 |
| **Capacitor/WebView 套壳**（现有页面包成 APK） | ≈1~1.5 人日 | **0 元**（APK 侧载分发，不进商店） | 可加推送/原生能力，可后续上架 | 推荐第二阶段 |
| 原生/跨端重写（Flutter/RN） | 15~30 人日 | 开发者账号费（见下） | 最佳 | 暂不建议 |


## 三、成本计算

### 1. 一次性成本

| 项目 | 金额 | 说明 |
| --- | --- | --- |
| 域名注册 | .cn 38~42 元 / .com 85~95 元（首年） | 云端部署必需 |
| ICP 备案 | **0 元**（云厂商代办） | 服务器在大陆则强制；7~20 工作日 |
| HTTPS 证书 | **0 元**（免费 DV / Let's Encrypt） | 3 个月一续 |
| **APP 备案** | **0 元** | 服务器在大陆的 APP 强制备案（2023 工信部新规），随 ICP 备案一起办；5~20 工作日 |

## 四、实施计划（三阶段）

### 阶段 1：云端部署 + 账号密码 + 手机绑定（核心，≈3 人日）

| 动作 | 文件 | 类型 |
| --- | --- | --- |
| SQLite 三表：users（username/scrypt 密码哈希/phone 绑定状态）、sessions、sms_codes；连接封装 | `src/fundamental_agent/auth/db.py` | 新增 |
| 短信客户端（阿里云或腾讯云，requests 自签；`SMS_MOCK=1` 时验证码写日志） | `src/fundamental_agent/auth/sms.py` | 新增 |
| 注册/登录/登出/绑定手机 + 验证码频控（60s/次、1h/5 次、24h/10 次）+ 会话管理 | `src/fundamental_agent/auth/service.py` | 新增 |
| 挂载 `/api/auth/register`、`/login`、`/logout`、`/bind_phone/send`、`/bind_phone/verify`、`/me`；FastAPI 加 CORSMiddleware（APP 跨域调用需要） | `src/fundamental_agent/api/server.py` | 修改 |
| Cookie 会话（`HttpOnly + SameSite=Lax`，HTTPS 加 `Secure`）、登录态校验中间层；APP 端可用 `Authorization: Bearer` 双通道 | `frontend/server.py` + `api/server.py` | 修改 |
| 登录页/注册页/绑定手机页（含 60s 倒计时、图形验证码防刷） | `frontend/login.html`、`frontend/bind_phone.html` | 新增 |
| 配置 `SMS_*` / `AUTH_SECRET` / `SMS_MOCK` 到 `.env.example` + `config.yaml` | `config.yaml`、`.env.example` | 修改 |
| 单测：注册登录、密码哈希、绑定流程、频控熔断、会话过期 | `tests/test_auth_*.py` | 新增 |


### 阶段 2：云上部署（≈1 人日，可与阶段 1 并行）

1. 买服务器（大陆轻量）→ 域名解析 → ICP 备案 + APP 备案（云厂商控制台提交）
2. uvicorn 前台 + FastAPI 后台，systemd 守护；Nginx 反代 + HTTPS；SQLite 定期备份 cron
3. 安全项：防火墙只开 443、失败登录锁定、验证码接口限流

### 阶段 3：APP 化（≈0.5~1.5 人日）

1. 先做 PWA：`manifest.json` + service worker + 图标，各页面补 viewport/@media 移动端适配排查（现有页面有部分响应式规则，需逐页核查）
2. 需要安装包时：Capacitor 包壳现有页面 → 签名 APK 直接分发（不进商店）
3. 上架诉求出现时再评估：先解决证券资质，否则维持侧载

## 五、关键风险与待确认

1. **证券牌照风险（最重要）**：只要走应用商店分发就绕不开《经营证券期货业务许可证》+ 交易所行情授权。确认走侧载/PWA 即可规避。
2. APP 目标用户是内部团队还是对外公众？——决定是否需要软著/商店上架/经营性 ICP 许可证（对外收费经营需《增值电信业务经营许可证》）。
3. 短信服务商选阿里云还是腾讯云（单价持平，签名审核均需 1~2 工作日）；云账号是个人还是企业实名（影响签名报备）。
4. iOS 分发确认：无企业签名条件下，iOS 用户首选用 PWA（Safari 添加到主屏），TestFlight 内测上限 1 万人。

## 实施记录（AUTH-A/B/C，2026-09-11 落地：路由访问权限控制）

- **AUTH-A `frontend/server.py`**：页面级路由拦截——白名单（login/register/reset_password、css/js、/api/auth）外的一切 GET/POST 均需有效 `ta_session` 会话（经 8002 `/api/auth/me` 校验 SQLite 会话，fail-closed）；未登录访问页面 302 → `/login.html?next=<原路径>`（登录后原路返回），未登录调用 API → 401 JSON；已登录访问 `/login.html` → 302 回首页。
- **AUTH-B `api/server.py` + `login.html` + `index.html`**：FastAPI `/api/*`（除 `/api/auth/*`）中间件门禁（Cookie/Bearer 双通道，OPTIONS 放行）；登录页已登录自动跳首页（或 next）；登录成功 honor `?next=`（同站相对路径，防 Open Redirect）；首页导航栏加「退出」按钮（/api/auth/logout → 回登录页）。
- **AUTH-C 端到端验证 10/10**：未登录访问首页/个股页 302 带 next、登录成功进首页、刷新持久化、已登录访问登录页自动跳转、未登录 API 401、会话过期（DB 过期时间）重跳登录、登出后再访问重跳登录。
- 会话持久化：未勾选「记住我」= 浏览器会话 Cookie（服务端 3 天）；勾选 = Max-Age 30 天持久化（服务端 30 天），刷新/重开浏览器均保持。
