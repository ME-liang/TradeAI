# 报告生成任务模型与状态隔离（含状态串扰事故复盘）

> 适用：`POST /api/report` 异步任务（概况 / 基本面 / 行业对比 / 板块深度报告）。
> 复盘日期：2026-09-11。

## 一、任务模型（现状）

| 环节 | 实现 | 文件 |
|---|---|---|
| 任务创建 | `TaskManager.create(code, bk, report_type)` → 12 位 uuid；**仅当 code+bk+report_type 都相同且状态为 PENDING/RUNNING 时复用**（避免同类型重复打接口） | `src/fundamental_agent/api/tasks.py` |
| 任务执行 | 每个任务一个 daemon 线程跑 `_worker` → `run_pipeline(report_type=…)` | `src/fundamental_agent/api/server.py` |
| 状态上报 | worker 经 `tm.update(task_id, stage/progress/status/html_path)` 回写**自己任务**的状态槽 | 同上 |
| 进度轮询 | `GET /api/report/{task_id}` 返回该任务独立状态 | 同上 |
| 产物落盘 | `output/reports/{code}/[{report_type}/]{date}/report.html`（**按类型物理隔离**）+ `profile.json` + `meta.json` | `src/fundamental_agent/storage.py` |
| 当日复用 | 同 code+report_type（industry 另加 bk）当日已有 SUCCESS 产物 → 直接复用（`force=true` 跳过） | `api/server.py: _reuse_today` |
| 前端 | 三类报告各自维护 `ovTaskId/fundTaskId/indTaskId` + 独立轮询定时器 + 独立 iframe 面板 | `frontend/stock_detail.html` |

**隔离的三道保障**：①任务标识（tm 去重键）②任务状态槽（按 task_id）③产物路径（按 report_type）。

## 二、事故复盘：概况报告被基本面报告覆盖（2026-09-11，已修复）

### 现象
先点「AI生成公司概况报告」，再点「AI生成基本面分析报告」→ 两份报告同时生成，**概况面板显示的是基本面报告**。

### 根因（唯一根因，已实测复现）
`TaskManager.create` 的**去重键缺少 `report_type`**：

```python
# 修复前
if t.code == code and t.bk == bk and t.status in ("PENDING", "RUNNING"):
    return t          # ← 概况任务 RUNNING 时，基本面请求也命中这里
```

机制链条：

1. 概况任务 A 创建（RUNNING，正在生成概况报告）；
2. 点基本面 → `create_report` 调 `tm.create(code, bk)` → **命中 A 并原样返回**（code/bk 相同、状态 RUNNING），**没有创建新任务**；
3. 但调用方仍以 `report_type=fundamental` **启动了第二个 worker 线程**，并把 **A 的 task_id** 传给它；
4. 两个 worker 并发共用同一个 task_id，交替 `tm.update()` → `stage`/`progress` 交叉，**最终 `html_path` 由后完成的 writer 决定**（实测为基本面路径）；
5. 前端两个面板各自轮询**同一个 task_id** → 概况面板的 iframe 加载到基本面报告（实测两面板 `src` 完全相同，均指向基本面产物）。

补充证据（插桩实测）：两次 POST 返回同一 task_id（`d51a960cd16c`），该任务最终 `html_path` 指向 `…/fundamental/…/report.html`；而磁盘上 `…/overview/…/report.html` 内容仍是正确的概况报告 —— 证明**不是文件互相覆盖，而是任务状态槽被两个 worker 争用 + 前端被指向同一任务**。

### 修复
把 `report_type` 纳入任务标识（三文件小改，无接口破坏）：

| 文件 | 改动 |
|---|---|
| `api/schemas.py` | `TaskStatus` 新增 `report_type: str = ""` |
| `api/tasks.py` | `create(code, bk, report_type)`；去重条件加入 `report_type` 比对 |
| `api/server.py` | 三处 `tm.create(...)` 传入 `report_type`（board / 复用分支 / 常规分支） |

修复后行为：
- `code+bk+report_type` 全同且仍在跑 → 复用（原「避免重复打接口」语义保留）；
- 任一项不同 → 新建独立任务，各自独立状态槽与产物路径。

### 验证（修复后实测）
1. **三类型并发**：POST overview / fundamental / industry 连续提交 → 返回 **3 个互不相同的 task_id**，`report_type` 字段各自正确；
2. **同类型去重仍生效**：重复提交 overview → 返回同一个 task_id（不重复起任务）；
3. **前端真实点击复现转绿**：概况任务 `71ed85cd8dcc` vs 基本面任务 `adbe0e4857f9`（不同），两 iframe src 不同，概况面板内容=概况报告、基本面面板内容=基本面报告，磁盘两份产物内容各自正确；
4. **行业报告单独验证**：`300184 + BK0890` → SUCCESS，落盘 `output/reports/300184/industry/20260911/report.html`。

## 三、遗留与建议

1. **行业报告数据问题（与本次修复无关）**：`002384 + BK1036` 失败于「竞品识别失败：未在市场快照中找到该股票」——属行业报告自身的市场快照覆盖/板块成分匹配问题，建议单独排查（换板块或用快照覆盖内的个股可正常出报告）。
2. **更严格的隔离（可选增强）**：`/api/report/{task_id}/html` 可校验 `task.report_type` 与预期一致；前端可在拿到 task_id 后比对「同股其他类型任务 id」并在相同告警（防御性，当前已无实际风险）。
3. **任务可见性（可选）**：`GET /api/report?code=…` 列出该股全部任务（含类型），便于前端在刷新后恢复三个面板的进度。
