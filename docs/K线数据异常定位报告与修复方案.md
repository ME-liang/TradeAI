# K 线数据异常：定位报告与修复方案

- 定位日期：2026-09-25
- 触发来源：用户截图（个股日 K，2026-02-27 ~ 2026-09-24，图中出现一根跨越 13→20 的粗长红柱，以及一根拉至 16.5 又回落的细长上影）
- 影响范围：**全市场个股的日/周/月 K 线**，非个别标的
- 结论：**唯一根因是 `push2test` 主机被用于取历史 K 线**

---

## 一、结论（一句话）

`frontend/server.py` 的 K 线主机池 `KLINE_HOSTS` 里含 `https://push2test.eastmoney.com`；
而 `fetch_stocks.ordered_hosts()` 把 `push2test`（唯一的大页主机）**排到所有路径的第一位**，
于是绝大多数个股的 K 线请求都打到这台主机 —— **它只对最近约 4 个交易日返回真实数据，更早的历史是随机生成的占位样本**。

## 三、取证

### 3.1 同一请求打到不同主机（code=603050 科林电气）

| 主机 | 返回行数 | 日期跨度 | 单日跳变(>21.5%) | 判定 |
|---|---|---|---|---|
| `push2his` | **2297** | 2017-04-14（上市首日）→ 2026-09-24 | **0** | 真实、完整 |
| `push2test` | **80** | 2026-02-27 → 2026-09-24 | **10** | 残缺 + 脏 |
| `push2delay` | 0 | — | — | 不支持 kline |
| `push2` | 0 | — | — | 不支持 kline |

`push2test` 的脏行长这样（`date, o, c, h, l, vol`）：

```

2026-07-04  22.28  22.28  22.28  22.28      205     ← 与上一行相差 4 倍
```

真行成交量 2.4 万 ~ 22 万手，脏行 1 ~ 980 手（相差 4 个数量级），且大量行满足 `o=c=h=l` 的常数值。

### 3.3 窗口对**所有**个股固定

抽样 160 只，`push2test` 的 K 线**首根恒为 2026-02-27、末根恒为 2026-09-24**，行数 10 ~ 104 根，
与个股上市日期无关（688825 只上市 44 天也返回 24 根；000088 上市 29 年也只返回 104 根）。

把这条套回截图：**截图左上角的时间标签恰是 `2026-02-27 ~ 2026-09-24`**，
且 `win=120 > 104` 时窗口即全量数据 —— 与 `push2test` 的固定窗口完全吻合。

### 3.4 为什么会被"优先选中"

```python
# fetch_stocks.py:45
BIG_PAGE_HOSTS = frozenset({"https://push2test.eastmoney.com"})   # 唯一成员

# fetch_stocks.py:56-80（修复前；现版已参数化 prefer_big_page）
def ordered_hosts(hosts=None):
    def rank(h):
        cooling = 1 if _host_down_until.get(h, 0.0) > now else 0
        big = 0 if h in BIG_PAGE_HOSTS else 1        # <- push2test 恒为 0，恒排第一
        return (cooling, big)
    return sorted(hosts, key=rank)
```

```python
# server.py:558-562  K 线主机池（修复前含 push2test）
KLINE_HOSTS = [
    "https://push2his.eastmoney.com",
    "https://push2delay.eastmoney.com",
    "https://push2test.eastmoney.com",
    "https://push2.eastmoney.com",
]
# server.py:620  _push2_try -> fetch_stocks.ordered_hosts(hosts or PUSH2_HOSTS)
```

**`big` 这个排序键是 2026-09-24 为「列表页分页」加的**：`push2test` 在 `clist` 上支持 `pz=1000`
（6 页拉完全市场，而 `push2delay` 被钳到 100 条/页要 56 页），页数少 = 不容易被判定为爬虫。
这个优化对 `clist` 成立，但它被**无条件套用到了所有路径**，包括 K 线。

### 3.5 为什么一直没被发现

因为 `push2test` **对"当前值"是真的，只对"历史序列"造假**：

- 股票列表页 / 个股快照 / 板块列表 / 板块成分 → 只读当前值 → **不受影响**，看起来一切正常；
- K 线（周/月/日）→ 要的是历史序列 → **全线污染**；
- 且日 K 的 `fetchN=600`、`win=120` 让用户只看最近 120 根，脏数据被"切碎混入"，不易一眼看穿。

（历史记录里曾有一条判断"push2test 实测可正常返回 kline（含 f57 逐根成交额）"——
**"能返回"不等于"返回正确"**，这条判断只验证了字段存在性，没有验证数据质量，是本缺陷得以存活的原因。）

## 四、附带发现（不同根因，需一并处理）

### 4.1 东财 `fqt=1`（前复权）对高分红股会产出 ≤ 0 的价格

`push2his` 对老股票的长历史段：

```
002048 宁波华翔（push2his, fqt=1）
  2006-05-12   o=-2.07  c=-1.78  h=-1.78  l=-2.13
  2006-05-16   o=-1.64  c=-2.15  h=-1.62  l=-2.15
  
000088 盐田港（push2his, fqt=1）
  1997-07-29   o=0.59  c=0.81  h=0.81  l=0.56
```

前复权 = 不复权价 × 复权因子，因子随累计分红送转单调递减；当累计分红超过历史价格时，前复权价被压到 0 甚至负数。
`push2his` 忽略 `lmt`（请求 600 根却返回 2297/6920 根全量），所以这些负价段**确实会进入数组**，
只是被 `klines[-n:]` 截掉。

**当前真实影响有限**（日 K 取 600 根 ≈ 回溯 2.4 年；周/月 K 窗口固定 120 根），
但这是**同一类问题的另一面**：采信上游前没有做值域校验。若将来放开窗口跨度或改用 `beg`/`end` 拉长历史，会立刻暴露。

### 4.2 `lmt` 被 `push2his` 忽略

请求 600 根返回 2297~6920 根全量（`lmt` 无效），每次无谓传输数十倍数据。
现在靠 `klines[-n:]` 兜住，行为正确但代价浪费；若要缩小，应改用 `beg`/`end` 真实日期区间。

## 五、修复方案

### R1 根因修复：K 线不再使用 `push2test`（必做）

- `server.py:558-562`：从 `KLINE_HOSTS` 中移除 `https://push2test.eastmoney.com`。
- `fetch_stocks.ordered_hosts()` 增加关键字参数 `prefer_big_page=True`，`_push2_try()` / `_push2_each()` 同名透传；
  **只有 `clist` 分页相关调用点传 `True`（保持现状），K 线传 `False`**。
- 理由：页容量是 `clist` 分页场景的指标，对 K 线毫无意义，却把一台只有"当前值"可信的主机排到了首位。

> 只改主机池不改排序，仍可能在别处被绕过；两处都改才封得住。

### R2 护栏：K 线响应必须过完整性校验（必做）

在 `server.py` 新增：

```python
def kline_quality_check(d, klt, n) -> tuple[bool, str]:
    """K 线响应完整性校验。不通过则整份丢弃——残缺/脏数据永不采纳、永不落缓存。"""
```

判据（任一不过 → 拒绝）：

1. `dates` / `candle` / `vols` 三者等长且非空；
2. `candle` 每项为长度 4 的 OHLC，且 `low ≤ min(o,c) ≤ max(o,c) ≤ high`，四值全部 `> 0`；
3. 日期严格递增、无重复，形如 `YYYY-MM-DD`；
4. 单日涨跌幅 `|Δ|` 不超阈值（日 K 21.5% / 周 K 45% / 月 K 90%，覆盖各板块上限 + 长期上限）；
5. **连通性判据**：任意 20 根滚动窗口内出现 ≥ 3 次超阈值跳变 → 判定"两档价位混排"，直接拒绝；
6. **与基准源交叉校验**：同一日期与腾讯 qfq 收盘价偏差 > 5% 的根数占比 > 10% → 拒绝该源。

第 6 条是兜住"内部自洽但整体错"的那类（`push2test` 对某些个股跳变数就是 0，单看形态查不出来）。

### R3 竞速改造：先校验，再采纳（必做）

`fetch_kline()`（server.py:1413-1458）现在是"东财/腾讯并行竞速，**首个非空者胜**"——
脏的东财因为响应小、返回快而获胜。改为：

- 并行竞速 → **首个"校验通过"者胜**；
- 串行兜底链（eastmoney → tencent → sina）同样每源先校验；
- 全部不通过 → 抛 `MarketSourceUnavailable`（沿用 `fetch_stocks` 的既有异常约定），**不落 `_KLINE_CACHE`**。

### R4 缓存卫生（必做）

- `_kline_cache_put()` 写入前必须已通过 R2 校验（双保险：读取命中时也复验一次）。
- 缓存值增加 `source` 与 `quality` 元信息。
- 部署时重启前端服务即可清空 `_KLINE_CACHE`（纯内存，无落盘）。

### R5 前端三态：脏数据不得当真实行情展示（必做）

`/api/kline` 增加 `data_status`（`ok` / `degraded` / `unavailable`）与 `source` 字段；`stock_detail.html`：

- `data_status !== 'ok'` → 复用 `#kDemo` 那套提示条文案（改为"K 线数据源异常，暂无法展示真实行情"）；
- **删除 `fetchKline()` 的 `.catch()` 里静默 `genData()` 合成数据的分支**（server.py 侧 K 线已无降级；
  前端拿不到真实数据就明确告知不可用，不再用随机数据冒充行情）——
  这与项目既有取向一致（`stock.html` 的 `FALLBACK` 假数据兜底已被认定为信任类问题）。

### R6 前复权负价（建议做，与 R2 同源）

- 方案 A（推荐）：前端按需请求区间 —— `beg`/`end` 传真实日期，只拉视窗所需跨度，不在后端一次拉全历史；
- 方案 B：保留 `fqt=1`，但在校验里把 `≤0` 的价格判为不可用并**截断到第一个正常价格**；
- 方案 C：改用 `fqt=2`（后复权）——后复权不会出现负价，但与现网"前复权"口径不同，需产品确认。

### R7 可观测（建议做）

在启动自检 / 定时自检里增加一条 **K 线跨源一致性抽查**（抽 3~5 只，东财 vs 腾讯比最近 20 根），
把"上游悄悄返回错数据"从"靠用户截图发现"变成"自检告警"。

### 8.2 与本文档 §五 原方案的差异（**重要**）

原方案中若干阈值与判据是**估计值**，实施时用实测数据重新标定，四处改动：

1. **R2 判据 4（涨跌幅上限）**：原写"日 21.5% / 周 45% / 月 90%"，实测（9 只 × 日/周/月，可视窗口内）真实最大单根为 **日 12.7% / 周 52.1% / 月 66.4%** → 最终取 **21.5 / 80 / 150**（周、月上调，避免误杀）。
2. **R2 判据 6（跨源偏差阈值）**：原写 5%，但实测两源在**可视窗口 120 根内**的最大偏差只有 **0.55%**（日 0.13 / 周 0.50 / 月 0.55）→ 收紧到 **1.5%**（3 倍余量）。
3. **R2 判据 5（连通性）**：原"任意 20 根滚动窗口内 ≥3 次跳变"，改为**整份响应最近 `KLINE_WINDOW=120` 根内 ≥ `KLINE_JUMP_MAX_COUNT=3` 次**（更简单，且与前端可视窗口对齐）。另新增**方向性判据**：若同期存在**没有该跳变**的对照源，则剔除带跳变的一方（解决"对称交叉比对把两个源同时否掉"的边界）。
4. **新增两档语义 + 行数比**：原方案只有"通过 / 拒绝"两态，实施时拆成三档——`reason`（否决，整份丢弃）/ `warnings`（通过但 → `data_status=degraded`）/ `notes`（仅记录，**不影响** `data_status`，用于"可视窗口之外的历史伪影"）。并新增 `KLINE_LEN_RATIO_MIN=0.8`（相对对照源的行数比下限；实测两源对同一 `lmt` 截断后**行数比恒为 1.000**）。
5. **R3 由"首个校验通过者胜"改为"双源竞速 + 交叉确认"**：单源自洽但整体错时（`push2test` 对某些个股跳变数就是 0），单源自校验查不出来。故改为**收齐两源（首源返回后宽限 `KLINE_PEER_GRACE=2.5s`）→ 两两交叉确认 → 按优先序取**；无对照源时才退化为单源自校验并记 `xcheck=skipped`。
6. **`/api/kline` 契约收紧**：原方案只说"增加 `data_status`"，实施时明确为**三种情形（成功 / 降级 / 不可用）一律 HTTP 200**，不可用态完全由 `data_status` 表达（与 `get_market_data` / `handle_api_stocks` 既有约定一致），**任何情形都不合成数据**。

> 另：R2 的"整份丢弃"只用于**结构类**判据（等长 / 日期严格递增 / `YYYY-MM-DD` / OHLC 4 项 / `hi < lo` 等）；**值域类**只看最近 120 根。原因是**必须限定可视窗口**——全序列跨源比对会误杀：月 K 在远古近零价区间两源偏差爆炸（实测 000088 达 824%），那是"0.02 vs 0.20"量级差，不是数据错误。
